kWh Electric — UI snippet correction brief

Deck E product visuals rejected — rebuilding from scratch

Deck version E's "MacBook screen" panels were wrong. Most of them were a diagram or an icon list pasted inside a laptop-shaped frame — not an actual recreation of the kWh product's UI. That's not acceptable: every panel that claims to be a product screen has to look like it was genuinely captured from the running app, using its real layout, real navigation, real copy, and real data shapes. No shortcuts, no invented dashboards that only vaguely resemble software.

This file has two parts:

  • Two corrected snippets — Fleet / Gateway Overview and Asset Management — rebuilt faithfully from real screenshots of the actual kWh Electric gateway management UI and Grid Intelligence utility portal supplied earlier in this project. These are the quality bar: this level of fidelity, on every future "product screen" slide.
  • Detailed written specs for the screens that failed in Deck E (any-asset/protocol, onboarding, grid services/dispatch, customer payout, security) — since faking these again would repeat the same mistake, each one is written out in enough detail that whoever builds it next (a designer, or another AI) knows exactly what real UI needs to exist, instead of guessing.

Non-negotiable rules for anything built from this brief:

  • No drop shadows anywhere. Flat panels, thin 1px borders, done.
  • A "product screen" snippet is a screenshot recreation, not a diagram wearing a UI costume. If the real screen's layout, nav, and copy aren't known precisely, don't invent a plausible-looking substitute — say so and describe what's needed instead (see the spec sections below).
  • Colors: kWh's own green (#16A34A), the pale green-tinted surface (#F2F8F4) and white cards — these are the actual design tokens already in production at kwh-forecasting/design-system.html. Match the structural polish and realism of a well-produced SaaS screenshot (sharp alignment, real data density, a real top bar and nav) — just never in purple, never dark.
  • These are standalone snippets, not full slides. No headline, no body copy, no "Slide N" framing — just the UI, cropped tight, ready to be dropped into a layout later.

Spec — any asset & any protocol

Deck E rendered this as a generic three-icon-groups-into-a-box diagram. That's not a product screen. The real equivalent already exists in the gateway UI as the Northbound and Southbound tabs visible in Snippet 1's tab strip.

What this snippet needs

  1. Southbound tab: a list or card grid of protocol adapters actually configured on the gateway — each card shows protocol name (Modbus TCP, SunSpec Modbus, RS-485, CAN 2.0B, MQTT, OCPP), connection status (connected/disconnected), and device count bound to that adapter. This is the real "any protocol" story — don't invent a translator diagram, show the adapter list.
  2. Northbound tab: the IEEE 2030.5 server configuration panel — endpoint URL, certificate status, tenant, poll rate. This is the real "one language upstream" story.
  3. If neither tab has been screenshotted from the live gateway yet, that's the actual next step before this snippet can be built accurately — capture both tabs from http://192.168.33.43:9080/ui/ (or whichever gateway is live) rather than approximating from memory.
Reference: the real gateway's tab strip (Overview / Northbound / Southbound / DER / Control / Telemetry / Normalization / Network / Security / Logs / Updates / Settings) is already captured correctly in Snippet 1 above.
